# ADR-0005: The API reaches Postgres through synchronous SQLAlchemy 2, with Alembic migrations

**Date**: 2026-11-16
**Status**: proposed
**Deciders**: Peter Wright

## Context

ADR-0002 puts the data in Postgres but leaves open how the API reads and writes it. The API has no database code yet, and the first feature that stores data (authentication) needs tables, a way to change them over time, and tests against a real database. The choice binds every later feature.

## Decision

The API uses SQLAlchemy 2 with typed declarative models and the psycopg 3 driver, in synchronous mode. Alembic owns the schema: every change is a migration in `atletico_hub/db/migrations/`, applied with `alembic upgrade head` before the API starts. Features reach the database through repositories that wrap a SQLAlchemy session.

## Alternatives Considered

### Alternative 1: psycopg 3 with hand-written SQL, Alembic for migrations
- **Pros**: no ORM layer; every query is visible SQL
- **Cons**: mapping rows to objects and building queries by hand in every repository
- **Why not**: more code to write and test for a small team, with no performance need for it

### Alternative 2: SQLModel
- **Pros**: one class is both the Pydantic schema and the table
- **Cons**: couples API shapes to tables; lags behind SQLAlchemy and Pydantic releases
- **Why not**: API models and tables change for different reasons, so they stay apart

### Alternative 3: async SQLAlchemy with asyncpg
- **Pros**: no thread pool for database calls
- **Cons**: async session pitfalls (lazy loading), more complex tests
- **Why not**: the app has few users; synchronous code is simpler to write and test

## Consequences

### Positive
- The most documented FastAPI and Postgres pairing; the agent skills apply
- Autogenerated migrations, checked against the models by a drift test

### Negative
- An ORM to learn, and SQL hidden behind it
- Database routes are plain `def` functions run in FastAPI's thread pool

### Risks
- A model changed without a migration. Mitigation: the drift test fails in CI
